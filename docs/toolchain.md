# Toolchain

The pinned toolchain, the per-library compiler profiles and the data-layout notes. Moved out of `AGENTS.md` unchanged; read the row of the library you are working on. The verb table is `docs/tools.md`.

**Toolchain** (pinned; binaries are gitignored, versions recorded here):
- Compiler: CodeWarrior for Wii `Wii/1.0` (mwcceppc 4.3 build 145), chosen from the RVL SDK banner
  `Feb 27 2009 (0x4302_145)`. Linker: `Wii/1.0` mwldeppc. Local copies in `tools/compilers/Wii/*` (also 1.0RC1,
  1.0a, 1.1, 1.3, 1.5, 1.6, 1.7, 0x4201_127 and GC versions for experiments).
- Base cflags: `-nodefaults -proc gekko -align powerpc -enum int -fp hardware -Cpp_exceptions off -O4,p
  -inline auto -pragma "cats off" -pragma "warn_notinlined off" -maxerrors 1 -nosyspath -RTTI off -fp_contract on
  -str reuse -multibyte -i include`. Per-library overrides go in the `RVLSDKLib` / `MiddlewareLib` / `GameLib`
  helpers and the library dicts in `configure.py`.

  Data layout notes: small (`.sbss`) uninitialised (tentative) statics are emitted in reverse declaration order,
  statics initialised to zero in declaration order. Larger uninitialised `.bss` statics depend on `-pool`: under the
  default `-pool on` they are pooled (later ones addressed off the first one's base register) and laid out in order
  of first use in the code (OSPlayRecord); only under `-pool off` are they in reverse declaration order (MetroTRK
  EXI2_GDEV_GCN/main). The RVL SDK is built with the default: `-pool off` breaks 31 SDK functions (docs/exceptions.md,
  "DVD rulings (sdk-io-3)"). objdiff does not verify static layout: it reports 100% for a unit
  whose statics sit in the wrong order while the DOL hash fails (OSStateTM). Only the gate proves a unit's
  `.data`/`.bss`/`.sbss` layout; flip a unit to `Matching` on the gate, never on objdiff alone. Linker-table entries nothing names (`__init_cpp_exceptions_reference`
  etc.) are listed under `force_active` in `config.yml`. A game unit that nothing outside it references (a Climax behaviour reached only
  through the class registry its `__sinit` fills) is stripped by MWLD, which keeps an object's `.ctors` only when
  another section of it is live: list its class registration object (`unk_801A8F6C lbl_...`) under `force_active`.
  Confirm first in the retail asm that no other file names any of the unit's symbols; if one does, the split is wrong. A source unit followed by a dtk asm unit (4-byte
  aligned) must end its `.text` split at its last instruction, not at the next 16-byte boundary.

All are built with one command, `tools/build_c.cmd [--test] [--parallel N]`
  (a wrapper over the CMake presets in `tools/c/CMakePresets.json`; CMake 4.x, found by `build_c.cmd` through `SHSM_CMAKE`
  (full path of `cmake.exe`) or else on `PATH`; MSVC 2022, x64, `/W4 /WX`; executables in `build/tools/`). Unit tests are
  CTest (`ctest --preset tools [-L <tool>] [-R <pattern>]` in `tools/c`). Each port was proven equal to its Python
  original by a differential harness; the Python tools and the harness were retired in commit 66ee84d3 (the C ports
  became the defaults in af1eba9), and each tool's `DEVIATIONS.md` is the proof record. `configure.py` remains as the
  project's unit table, read by `build/tools/configure.exe`. The only Python left is the third-party decomp-permuter.
  The porting recipe and the library API are in `tools/c/README.md`.
