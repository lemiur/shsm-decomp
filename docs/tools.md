# Project tools

The project adapter: the verb table the skills (`matcher`, `wall-identifier`, `helper-recovery`, `permute`, `orchestrator`) use, with the paragraphs about running the tools. Moved out of `AGENTS.md` unchanged; every tool also prints its own options with `--help`. Compiler flags and per-library profiles are in `docs/toolchain.md`.

## Project adapter

All commands run from the repository root (Git Bash shown; PowerShell works the same with `\` paths).
Unit names are `main/<path without extension>`, for example `main/Runtime.PPCEABI.H/__init_cpp_exceptions`
(see `objdiff.json` after configuring).

| verb | meaning | this project's command |
|---|---|---|
| `pick` | ranked work lists: what to work on next | `build/tools/pick.exe [lost\|close\|near\|fresh\|pending\|drafts] [--lib L] [--unit U] [--min-size N] [--max-size N] [--limit N \| --all] [--json]`: lost matches (historical above current), `NonMatching` units by how little is left, near-exact functions (`--threshold P`), unstarted functions (`--small`, `--leaf`, `--tiny N`), `MATCH-PENDING` functions (`--checker`), unstarted twin targets that `draft` grades MATCH in its last sweep (`drafts`; says so with the `sweep` command when `build/draft/sweep.json` is absent or older than the asm index); without a mode, a short section of each. Libraries are attributed by address from `config/R5WEA4/libraries.tsv` (transcribed from `docs/library_map.md`) |
| `brief` | the starting briefing for one function or unit | `build/tools/brief.exe <symbol or address> [--section NAME[,NAME]] [--lines N] [--full] [--asm \| --no-listing] [--no-compile] [--json]`, or `build/tools/brief.exe --unit <unit or START-END>`: one capped page (identity, status, twins, context, shape, listing, where to start) stitched from `query`, `twins`, `pick`, `wall`, `classes`, `unit_plan`, `decomp` and `match`'s saved state, plus, when their data exists, the `eqcheck` verdict, the PS2 counterpart and inlined helpers (`witness`), the Gormiti counterpart of the function (an unpaired function whose real name exists in the sibling gets a same-named line pointing at `sibling.exe fn`) or the sibling object spans of a `START-END` range (marked when the range is the proposed unit range of `sibling.exe units`; a range that is only the paired span prints the proposal) (`sibling`, when `build/index/sibling` exists) and `draft.exe twin` for a function with a matched exact twin |
| `draft` | mechanical first drafts from matched twins | `build/tools/draft.exe select [--kind twin\|small\|leaf\|near] [--lib L]` (the queue), `packet <target> [--unit]` (the briefing and grading contract, and the first twin with its level), `twin [<function>] [--unit U] [--out DIR]` (the draft, written from the project's own matched source of the twin, never from a decompiler; it tries the matched twins in order, a `ref`-level twin (same relocation targets) first and the target's own library family before others, until one has a definition to clone, and records the level as `twin_level`; a member function is written inside the `namespace` its mangled name gives (`Q24FMOD…` is `FMOD`), and a class that a header under `include/` already defines is included, not cloned), `grade <target> --file F [--as-unit U] [--profile P]` (compile and score; a draft carrying decompiler artefacts is refused), `promote <path> --file F [--header H] [--text START-END] [--dry-run] [--allow-small-unit]` (puts a draft that grades MATCH into the tree as a parked `NonMatching` unit through `unit.exe new`, `names.exe rename` and `tools/bin/ninja.exe build.ninja`, undoing everything on a failed check; refuses a derived range that holds one function and is not a configured split unless `unit_plan` cuts it with high confidence on both sides (a block edge is no cut), `--allow-small-unit` overrides and an explicit `--text` is exempt; never flips and never commits), `reject <symbol> --reason R [--approach A]`, `rejects`, `sweep [--lib L] [-j N]` (twin and grade over the twin queue into `build/draft/sweep.json`; a target whose class in its own header already defines the member in the class body (`virtual ~X() {}`) is `SKIPPED`, not `FAIL`; a twin member defined in its header leaves a declaration in the cloned header, and an `fn_` target takes the namespaces of the twin's class); each with `--root DIR`, `--json`, `--limit N \| --all` |
| `unit_plan` | proposed unit boundaries for `.text` not yet split | `build/tools/unit_plan.exe START-END [--min-conf low\|medium\|high]` or `build/tools/unit_plan.exe --lib L`: proposed cuts, each with its evidence, under a header line stating the accuracy measured on the units already split; `build/tools/unit_plan.exe check [--detail]` prints that measurement. Cache `build/index/unit_plan.pickle` |
| `unit` | add, check, flip or park a unit | `build/tools/unit.exe new <path> --text START-END [--dry-run] [--regen]` (`<path>` is a `.c`, `.cpp`, `.cp` or `.s` file; a `.s` path gets an assembly stub, one `.fn`/`.endfn` pair per function under a `# <name>   // 0x8XXXXXXX` comment, in the form of `__exception.s`; splits.txt ranges with inferred data sections, the `configure.py` entry, source and header stubs (an existing header is left as it is and only the source stub is written, with a note); `--name-evidence "<text>"` writes that text in place of the "unit name unconfirmed" comment; a function the mangler qualifies with one name is stubbed inside `namespace X { }` when a header under `include/` declares that namespace, as a member definition when a header defines that class, and in the "signature not expanded" comment form when it declares neither (units without a generated header); `--dry-run` prints every data object next to the range as taken (with why) or not taken (with why and the `--include-data SYM` that takes it); a vtable the unit's code reads, a table of the unit's own function addresses and a jump table only it reads are taken by default; `--exclude-data SYM` leaves an object to another unit, and `new <path> --include-data SYM` without `--text` makes that data-only unit, e.g. a reference's `*_cfg.c`; a `--text` range with no blocks in `build/R5WEA4/asm` is refused unless `--allow-no-asm`; tools reading the unit table see the new unit only after `tools/bin/ninja.exe build.ninja`, which `new` prints and `--regen` runs), `resplit <path> --text START-END [--include-data SYM]... [--exclude-data SYM]... [--dry-run] [--regen]` (rewrites the splits.txt entry of an existing `NonMatching` unit in place, same data inference as `new`; refuses a `Matching` unit; configure.py and the source are not touched), `check <path>` (split end rule, symbols, address comments (`// 0x8XXXXXXX`, or `# ... // 0x8XXXXXXX` in a `.s` unit), `force_active` need), `flip <path>` (needs a clean tree and promotes only a `NonMatching` unit: runs `gatecheck layout` on the built object first when there is one, sets `Matching` and gates through `build/tools/gate.exe --pending-flip <path>`; on green it leaves `configure.py` edited for the caller to commit and gate again, on red it restores it and, when the built DOL's size differs from retail and nothing outside the unit references it, hints the `force_active` entry; each step announces itself when it starts, flushed, as `[ Ns] step <layout|gate|rules>: <what>` (N: seconds since the flip began; a default gate is silent until gate.exe ends, so the line says so); the gate's last `GATE ...` line is the last line printed; `--gate-cmd CMD` substitutes a custom gate), `park <path>` |
| `disasm` / `xref` / `class` | retail assembly, callers and callees, vtable and hierarchy evidence | `build/tools/query.exe fn <symbol>` (header and retail assembly; the listings are `build/R5WEA4/asm/<unit>.s`, written by `dtk dol split`, one `.fn` block per function), `callers <symbol>`, `callees`, `xref`, `strings`, `data`, `vtable` (see `query`); class: `build/tools/classes.exe scan` (writes `build/R5WEA4/classes.json`: vtables, sub-tables, bases, ctors/dtors, names with provenance, draft field layouts), then `show <class>` (each vtable word ends with `[introduced by <topmost base whose table has the slot>; held by <class whose function the table holds>; declare <the name under the project's convention: the introducing slot's fn_<address> plain name with the declaring class's mangling>]`, `(pure)` for a null entry in the introducing table, `inherited unchanged` for an inherited word, and a one-line legend under the vtable header; `<- Base` is only the next table up the chain), `tree [<class>]`, `header <class>` (a C++ skeleton with one virtual per slot; return types and field types are drafts to confirm; an override's comment adds `slot 0x.. introduced by X; held by Y`, plus the legend line in the banner), `decl <class> [--with-bases] [--header PATH [--force]] [--root DIR] [--json] [--limit N | --all]` (a compilable declaration draft: vtable ownership from the Gormiti `__vt__` object whose slots equal the retail table's, slot names from retail symbols, the `sibling` pairing, the Gormiti vtable order or a derived override (else `fn_` placeholders), overrides marked and inherited slots left out, members, return types and parameter names from the Gormiti DWARF with the vptr placed before the first virtual, `LAYOUT DIFFERS` notes against classes.json, the same introduced-by / held-by labels in each slot comment (from the classes.json chain of bases, which says an `override` here that classes.json calls inherited is only declared because the base table is unknown), the `needs:` types and their headers; a retail object holding two adjacent tables (a class's and its interface's) is split at the second header pair and both are reported, either drafted by its own name; an unqualified name resolves when unique (else the candidates are listed); a Gormiti table whose slots are game code is rejected for a middleware retail table, a namespaced class prefers the DWARF definition from a unit of its namespace and drops a same-named game definition when the sibling has no unit of that namespace; a class with no table equal to Gormiti's falls back to the table whose slots pair with it; a class without a vtable points to `sibling.exe types`; a member of function pointer type takes its parameter list (const included) from a retail mangled symbol that takes the same callback, when its spelling is unique; prints the symbols.txt renames and `scope:weak` changes it implies, each `scope:weak` (or vtable scope) with the ready `names.exe attr <symbol> --scope weak --apply` command; a class with no Gormiti DWARF type lists the fields classes.json drafts from the retail accesses as `field_0x<offset>` members marked as drafted) and `decl --stats` (per library group: classes with >= 90% of slots named, identified vtables, DWARF layouts); the readers warn when classes.json is stale (`--strict`: exit 1); `classes.exe scan` skips the `.s` listings the last split's record (`config.json` beside the asm directory) does not name and prints one note with their count, and keys bases by constructor and destructor evidence by default (the user's ruling, 2026-11-13; `--base-rule slots` selects the older slot-overlap rule) |
| `query` | ask the retail binary and the project a question | `build/tools/query.exe fn <sym> [--summary] [--raw]` (header and retail assembly), `callers <sym> [--depth N]`, `callees <sym> [--depth N]` (call trees), `xref <sym>` (every reference, grouped by kind), `strings <function\|unit>`, `find-string <text> [-e] [-i]`, `find-float <value> [--imm]`, `find-const <value>`, `data <sym> [--as u8\|u16\|u32\|float\|ptr]` (a data object as a C initialiser draft), `addr <address>`, `unit <unit> [--data]`, `vtable <vtable\|class>`, `notes <term> [--docs-only \| --source-only]` (docs and source comments that mention a term); every subcommand takes `--root DIR`, `--json`, `--limit N \| --all`. Reads the asm index `build/index/asm.sqlite` |
| `names` | demangle, mangle, find, rename and check names | `build/tools/names.exe demangle <name>...`, `mangle --name <name> [--class <A::B>] [--params "<list>"] [--const]`, `find <text>` (symbols.txt by raw or demangled substring), `attr <symbol|0x8XXXXXXX> [--scope global|local|weak] [--size N] [--align N] [--apply]` (changes the attributes of exactly one `symbols.txt` line; a dry run by default with the same final `DRY RUN` / `APPLIED` / `REFUSED` line as `rename` (`NO CHANGE` when the line already has the values); `--size` refuses to grow a symbol into the next symbol or past its unit's range and refuses a shrink that frees a range holding another symbol, and shrinking the last symbol of a unit's section also moves that section's `end:` in `splits.txt` to the new end (both edits printed); `--scope local` refuses a second `scope:local` symbol of the name in the same unit's ranges; a name several symbols carry is addressed as `0x8XXXXXXX`; `--align` takes a power of two; `splits.txt` is never edited on its own: a size that would leave the symbol's range crossing or falling short of its unit's section end is refused with the range and the end it would need (`use unit.exe resplit, or pass --resplit`), and only `--resplit` moves the section end, listing that edit in the dry run), `add <name> --section S --address 0x.. --size 0x.. [--type object|function] [--scope global|local|weak] [--align N] [--data D] [--apply]` (adds the `symbols.txt` line of a symbol that has none, e.g. the object left after a resize: inserted in address order within its section in the form of the neighbouring lines; a dry run by default with the same final `DRY RUN` / `APPLIED` / `REFUSED` line as `rename`; refuses an address that is already named, a range that overlaps a neighbour (the message names it and gives the `names.exe attr` that shrinks it), a range outside the section's ranges in `splits.txt` and a name that exists), `rename <old> <new> [--class] [--local] [--symbols-only] [--signature] [--family] [--apply]` (every place that must change together; a dry run without `--apply`, whose last line is always `DRY RUN: NOTHING WAS WRITTEN. Re-run with --apply ...` (`APPLIED: ...` or `REFUSED: ...` otherwise; the output cap never cuts it) and every refusal ends with a bracketed tag naming the rule that refused it and the flag, if any, that lifts it; a name collides only when the exact new name exists non-local, or when two `scope:local` symbols of the name would sit in one unit's `splits.txt` ranges (a name present only as locals of other units is free: the renamed line is made local when the old line was local or `--local` is given, else `--local` is asked for); `--signature`: the new name is a full mangled name that may change the class or the parameter codes (otherwise a rename keeps the signature): `symbols.txt` is rewritten, source only where the plain name changed, and the declarations and definitions under the old signature are printed as "to edit by hand" (file:line and text, filtered by class) beside the demangled old and new signatures; it refuses a new name that does not demangle, an existing non-local name and an address that would carry two names for one function; `--family`: every symbol with the same plain name and another class (the overrides of one virtual slot) changes together, each keeping its class: with `--signature` old and new give the change for one member and a member whose parameter codes differ is refused by name, without it the new name is a plain name and the "plain name also names other symbols" and "names symbols in N scopes" refusals are lifted; comments that mention a renamed `lbl_` placeholder are listed as "mentions in comments, not rewritten"; use `--all` to see every line of a long plan; a vtable, template, destructor, operator or mangled name with no source spelling is renamed in symbols.txt alone, automatically, with a note saying source was not touched and why and listing the source sites that name the old placeholder; the generated ledger `docs/progress.md`, the baseline report and `build/` are never edited, and the dry run notes their mentions), `check` (symbols.txt names against source objects and address comments); every subcommand takes `--root DIR`, `--json`, `--limit N \| --all` |

| `build` | compile every unit, compare every annotated function | `build/tools/configure.exe && tools/bin/ninja.exe` (dtk split, compile, link, SHA-1 check, objdiff report, progress) |
| `match <unit>` | compile and compare one unit quickly (the inner loop) | `build/tools/match.exe <unit> [SYMBOL...]` (built by `tools/build_c.cmd`): compiles the unit privately with its exact flags (an assembly `.s` unit is assembled by ninja's `as` rule instead and compared the same way; a `symbols.txt` or `splits.txt` newer than the unit's split asm prints a stale-asm warning: run `tools/bin/ninja.exe`; the compile cache is keyed on the source and the digests of every file the compiler's dependency file lists, so a header edit recompiles), compares every function with retail (instructions and ordered relocation targets) and prints objdiff's percent per function; `--diff SYMBOL [-C N] [--all-rows]` an aligned listing (capped at `--limit` rows, 40 by default; a cut ends with a line naming the rows cut and `--all` / `--limit 0`, which show them all), `--changed` only what moved since the last run (with no unit: every unit whose source or recorded header is newer than its last run or build, one row per unit and a total), `--file PATH` a variant source, `--built` the last ninja object, `--data` adds `gatecheck layout`, `--rules` adds the rule checker (exact + [match] = `MATCH-PENDING`); several units, `--status S` or `--lib L` with `-j N`; `--json`. | `rules [<unit>]` | the rule checker | `build/tools/check_rules.exe [<paths> \| --units main/<unit> \| --changed <rev>] [--json]` (default input `src/`). Tools share the C library (`tools/c/lib`, `tools/c/core`); `tools/c/README.md` is the API contract for anyone writing a tool.
`build/tools/asmindex.exe` builds or refreshes the retail asm index (`build/index/asm.sqlite`) that `query`,
`twins`, `pick` and the other search tools read (`--rebuild` drops it first, `--stats` prints row counts).

**Scoring one function.** The per-function score is objdiff's `match_percent` for that symbol:
```
build/tools/match.exe <unit> <symbol>
```
It prints `match_percent` per function and also checks the relocation targets. The raw form is
`tools/bin/objdiff-cli.exe diff -p . -u main/<unit> -o - <symbol>`, one-shot JSON in which `left` is retail (target)
and `right` is the compiled source (base); `right` is absent until the source compiles, and the symbol's
`match_percent` is in its `symbols` entry.
